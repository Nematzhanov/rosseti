# Как устроены модели и код

Этот файл объясняет, что делает каждая часть проекта, почему она устроена именно так и как пройти путь от сырых данных до прогноза на завтра. Цифры — из финального прогона на тестовом году 01.10.2025–29.09.2026.

## 1. Общая схема

```
сайт СО ЕЭС ──► download.py ──► raw/cache.jsonl ─┐
Open-Meteo  ──► weather/download_weather.py ─────┼─► model/common.py (признаки) ─┬─► model/train_lgbm.py   → LightGBM, базовые модели
isdayoff.ru ──► calendar/isdayoff_*.txt ─────────┘                               └─► model/train_chronos.py → Chronos-2
                                                                                           │
                    results/ (прогнозы, метрики) ◄─────────────────────────────────────────┤
                    model/report.py → results/REPORT.md                                    │
                    model/export_dashboard.py → dashboard/ (сайт с результатами)           │
                    model/predict.py ◄──────── checkpoints/chronos2-lora (дообученные веса)┘
                        ├─ gui/  (приложение Java Swing)
                        └─ webapp/ (веб-интерфейс)
```

## 2. Постановка задачи — главное правило всего кода

Прогноз на сутки **D** выпускается **накануне, в 09:00 МСК** — так работает планирование на рынке на сутки вперёд. На этот момент известны:

- фактическое потребление **до 08:00 суток D−1** включительно (`ISSUE_HOUR = 8` в `model/common.py`);
- **прогноз** погоды на сутки D (не фактическая погода — она ещё не наступила).

Модель выдаёт 24 часовых значения суток D. Это правило соблюдается везде: в признаках LightGBM, во входах Chronos-2, в проверке и в `predict.py`. Нарушить его — значит «подсмотреть будущее» и получить завышенную точность.

Метрика — **MAPE**, средняя абсолютная ошибка в процентах: `|прогноз − факт| / факт`, усреднённая по часам. Дополнительно — MAE в МВт и ошибка в час суточного пика.

## 3. Данные

### `download.py` — потребление
Страница «Генерация (час)» СО ЕЭС отдаёт одни сутки одной энергосистемы. Числа лежат прямо в HTML: `data-datay1` — генерация, `data-datay` — потребление (на сайте этот ряд скрыт, но в разметке он есть). Скрипт:

- запрашивает сутки по одной с паузой 2 с — на частые запросы сайт отвечает 503;
- при 503 ждёт 30, 60, 90… секунд и повторяет;
- складывает каждые сутки строкой в `raw/cache.jsonl` и при повторном запуске докачивает только недостающее;
- качает от свежих дат к старым, чтобы при обрыве оставался непрерывный хвост истории.

Собрано: 8 энергосистем (ЕЭС и 7 ОЭС), 01.01.2021–29.09.2026, по 2 098 суток. В трёх сутках на сайте 23 значения вместо 24 — эти часы заполняются интерполяцией.

### `weather/download_weather.py` — погода
Open-Meteo, 9 городов ОЭС Северо-Запада (Санкт-Петербург, Гатчина, Петрозаводск, Мурманск, Архангельск, Сыктывкар, Великий Новгород, Псков, Калининград). Значения усредняются с весами по численности населения. Три варианта:

| Набор | Что это | Где используется |
|---|---|---|
| `actual` | реанализ ERA5 — фактическая погода | обучение моделей |
| `hist_fcst` | архив оперативных прогнозов | погода прошлых дней на тесте |
| `dayahead` | прогноз, выпущенный за сутки | погода на целевые сутки на тесте |

### `calendar/` — производственный календарь
Коды isdayoff.ru: 0 — рабочий день, 1 — нерабочий, 2 — сокращённый. Нужен, чтобы модель отличала праздники и переносы выходных от обычных дней.

## 4. Признаки — `model/common.py`

Функция `make_features()` строит таблицу, где одна строка — один целевой час. Все признаки доступны на момент выпуска прогноза.

| Группа | Признаки | Зачем |
|---|---|---|
| Календарь | час, день недели, месяц, день года (sin/cos), тип дня D, D−1, D+1, D−2, D−7 | суточный и недельный ритм, праздники; тип дня у лагов — чтобы модель знала, что «неделю назад» был праздник |
| Лаги потребления | тот же час 2, 3, 7, 14 суток назад; последний известный час (D−1 08:00); среднее за утро D−1; среднее за сутки D−2; среднее за неделю | инерция потребления; лаг 24 ч не используется — на момент прогноза он ещё неизвестен для части часов |
| Погода на целевой час | температура, ощущаемая температура, влажность, точка росы, осадки, облачность, солнечная радиация, ветер | прямое влияние погоды |
| Производные | градусо-часы отопления `max(0, 16 − T)`; сглаженная температура с полупериодом 24 и 72 ч; минимум, максимум и среднее температуры суток | отопление включается ниже ~16 °C; здания остывают и прогреваются с задержкой |
| Погода в дни лагов | температура 2 и 7 суток назад, среднесуточная D−2 и её разница с D | модель учится поправке «было так-то при такой погоде — будет так-то при другой» |

## 5. Базовые модели и LightGBM — `model/train_lgbm.py`

### Схема проверки — расширяющееся окно
Тестовый год разбит на 12 месяцев. Для каждого месяца модель **заново обучается на всех данных, известных к его началу**, и прогнозирует этот месяц. Так модель всегда видит самую свежую историю, как при реальной эксплуатации.

### Модели
- **Наивная** — тот же час неделю назад. Точка отсчёта: MAPE 2,81 %.
- **Линейная регрессия** (`RidgeCV`) — категориальные признаки через one-hot, числовые стандартизированы. MAPE 1,20 %.
- **LightGBM** — градиентный бустинг деревьев решений:
  - параметры: `learning_rate=0.03`, `num_leaves=63`, `min_data_in_leaf=40`, подвыборки 80 %;
  - последние 56 суток обучающих данных — валидация; число деревьев подбирается ранней остановкой (200 итераций без улучшения), затем модель переобучается на всех данных;
  - три варианта: без погоды (1,39 %), с прогнозом погоды (0,97 %), с фактической погодой («оракул», 0,95 %).

**Почему LightGBM ошибается в морозы.** Дерево решений выдаёт значения только из диапазона, который видело в обучении. В сильный мороз потребление выше обычного, и модель «упирается» в потолок — занижает пики. Вариант с целью «доля от недельного среднего» (`lgb_ratio_fcst`) должен был это смягчить, но дал 1,06 % — хуже основного.

## 6. Chronos-2 — `model/train_chronos.py`

### Что это за модель
Chronos-2 (Amazon, 2025) — **предобученная модель временных рядов**: трансформер-энкодер на 120 млн параметров, обученный на тысячах разнородных рядов. Ряд режется на «патчи» по 16 точек; механизм группового внимания позволяет вместе с целевым рядом подавать **ковариаты** — внешние ряды, в том числе известные в будущем. Модель выдаёт не одно число, а квантили — отсюда коридор 10–90 %.

### Входы
Для каждых целевых суток D (функция `build_inputs`):

- `target` — потребление за последние `ctx` часов до D−1 08:00 (2048 ч ≈ 85 суток без дообучения, 1024 ч при дообучении);
- `past_covariates` — для тех же часов: температура, ветер, облачность, солнечная радиация, флаг нерабочего дня, флаг сокращённого дня;
- `future_covariates` — те же 6 рядов на 39 часов вперёд (`PRED_LEN = 39`: с D−1 09:00 до D 23:00), погода — из прогноза.

Модель прогнозирует 39 часов, в зачёт идут последние 24 — сутки D. Точечный прогноз — медиана (квантиль 0,5).

### Режимы
| Режим | Как | MAPE |
|---|---|---|
| Без дообучения, без погоды | только история потребления | 1,27 % |
| Без дообучения, с погодой | + 6 ковариат | 0,97 % |
| **Дообучение LoRA** | обучаются только маленькие добавочные матрицы в слоях внимания (~1–2 % параметров), `lr=3e-5`, 600 шагов, пакет 16, контекст 1024 | **0,84 %** |
| Полное дообучение | обновляются все 120 млн параметров, `lr=3e-6`, те же 600 шагов | 0,85 % |

Дообучение — один раз, на непрерывном ряде с 01.01.2021 по 30.09.2025 08:00 (41 601 час) с **фактической** погодой. Метод `Chronos2Pipeline.fit()` вырезает из ряда случайные окна и учит модель продолжать их.

### Особенности запуска на Mac (M3, 8 ГБ)
- **GPU Apple (MPS).** Устройство выбирается автоматически: CUDA → MPS → CPU.
- **Dropout.** Операция внимания на MPS не поддерживает dropout при обучении, поэтому перед `fit()` он обнуляется в конфиге модели. На прогноз это не влияет.
- **Память.** При пакете 32 и контексте 2048 система уходит в своп, поэтому для дообучения взяты пакет 16 и контекст 1024. Время: полное дообучение — 22 мин, LoRA — 47 мин (из-за свопа).

**Почему Chronos-2 лучше в морозы.** Нейросеть не ограничена диапазоном обучающих значений, как дерево: она продолжает форму кривой и сдвигает её уровень по ковариатам. В самую холодную неделю её ошибка — около 0,5 %, у LightGBM — 1,08 %.

### Ансамбль
Среднее прогнозов LightGBM и Chronos-2 без дообучения с погодой: 0,86 %, летом — лучший (0,78 %).

## 7. Прогноз на любые сутки — `model/predict.py`

То, что вызывают приложение и сайт:

```bash
.venv/bin/python model/predict.py --date 2026-10-06 --model chronos-lora --update
```

1. Загружает потребление из кэша. Если данных до D−1 08:00 нет и задан `--update` — докачивает недостающие сутки с сайта СО ЕЭС (в память, кэш не трогает).
2. Если дата свежее погодного архива — берёт из Open-Meteo последние 60 дней и прогноз на 3 дня; результат кэшируется на 3 часа.
3. Загружает дообученные веса `checkpoints/chronos2-lora/finetuned-ckpt` (или исходную модель для `chronos-zs`).
4. Строит входы так же, как в бэктесте, и считает квантили 10, 50 и 90 %.
5. Печатает результат строками между `RESULT_BEGIN` и `RESULT_END`: `meta ключ значение` и `row час прогноз p10 p90 факт температура`. Журнал идёт в stderr.

Один и тот же запрос всегда даёт один и тот же ответ: модель детерминирована, а данные на 09:00 накануне для прошедших суток уже не меняются.

## 8. Интерфейсы
- **`gui/src/ForecastApp.java`** — приложение на Java Swing без внешних библиотек. Запускает `predict.py` в фоне (`SwingWorker` + `ProcessBuilder`), разбирает строки `meta`/`row`, рисует график своими силами (`Graphics2D`). Запуск: `./gui/run.sh`.
- **`webapp/server.py` + `webapp/index.html`** — тот же интерфейс в браузере. Сервер на стандартной библиотеке Python, единственный метод API — `GET /api/forecast?date=…&model=…&update=1`; одновременно считается не больше одного прогноза. Запуск: `python3 webapp/server.py`, затем http://localhost:8790.
- **`dashboard/`** — статический сайт с результатами бэктеста (все данные встроены в страницу).

## 10. Ограничения
- Данные СО ЕЭС оперативные и могут уточняться задним числом.
- Веса городов — по населению, а не по потреблению субъектов.
- ОЭС Северо-Запада не равна Северо-Западному федеральному округу: Вологодская область входит в ОЭС Центра.
- Модели обучены и проверены для одной ОЭС; данные остальных 7 энергосистем собраны, но погода по их городам ещё не скачана.
